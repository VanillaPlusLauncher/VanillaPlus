# Режим разработчика и доступ для ИИ

Для тех, кто делает моды и проверяет их в Amethyx, в том числе с помощью ИИ (Claude Code, Cursor и других
программ с MCP). Для обычной игры не нужен. С 1.7.5.

## Как включить
1. «Настройки» → «Разработчик» → «Режим разработчика».
2. Для ИИ: «Доступ для ИИ (MCP)» → «Разрешить ИИ управлять лаунчером».
3. «Скопировать команду для Claude Code», вставить в терминал, перезапустить Claude Code. Для Cursor и других
   программ — «Скопировать настройку JSON» (раздел `mcpServers`).

Лаунчер должен быть открыт: доступ работает, пока он запущен. Адрес — `http://127.0.0.1:47615/mcp` (если порт
занят, берётся следующий; точный адрес — в настройках). Ключ хранится только на этом компьютере
(`<папка данных лаунчера>/dev-api.json`); «Новый ключ» сразу отключает старый. Выключение режима закрывает доступ.

## Что умеет ИИ
| Инструмент | Что делает |
|---|---|
| `launcher_status` | версия лаунчера, папка игры, аккаунт, что запущено |
| `list_instances` | сборки (`testOnly` — только тестовые) |
| `list_minecraft_versions`, `list_loader_versions` | версии Minecraft и Fabric / Quilt / Forge / NeoForge |
| `create_test_instance` | тестовая сборка: версия, загрузчик, моды (`"sodium"`, `"modrinth:sodium"`, `"curseforge:jei"`, путь к `.jar`, `{ "modrinth": "...", "version": "..." }`) |
| `add_mods`, `list_mods`, `remove_mod` | моды сборки |
| `launch_instance` | запуск с выбранным аккаунтом, возвращает `fromLine` |
| `wait_for_game` | ждёт строку журнала (`"Sound engine started"` — игра загрузилась), закрытие или вылет |
| `game_status`, `read_game_log` | что с игрой, журнал с номерами строк |
| `read_instance_log` | `logs/latest.log`, `debug.log`, копия последнего запуска, отчёт о вылете (с разбором) |
| `read_instance_file`, `write_instance_file` | файлы сборки (например конфиги; `instance.json` не пишется) |
| `stop_game`, `delete_instance` | закрыть игру, удалить сборку |
| `read_launcher_log` | журнал самого лаунчера |

Обычный цикл: собрал мод → `create_test_instance` с путём к `.jar` → `launch_instance` → `wait_for_game` →
`read_game_log` / `read_instance_log` → исправил → `add_mods` (тот же файл заменяется) → снова запуск.

## Защита сборок игрока
- Сборки, созданные ИИ, — тестовые: лежат в группе «Тесты ИИ», и ИИ меняет и удаляет их без вопроса.
- Удалить чужую (вашу) сборку, добавить или убрать в ней мод, изменить файл или закрыть игру, которую запустили вы,
  ИИ может только после «Разрешить» в окне лаунчера. Нет ответа за 2 минуты — это отказ.
- Копия тестовой сборки — уже обычная. Настройки, аккаунты и сам режим разработчика ИИ не меняет.
- Доступ только с этого компьютера (127.0.0.1) и только с ключом; веб-страницы в браузере достучаться не могут.
- «Что делал ИИ» показывает последние действия, «Удалить все тестовые» убирает тестовые сборки разом.
- Вылет тестовой сборки не открывает окно у игрока: запись уходит в уведомления, разбор ИИ читает сам.

## Запуск игры (на все сборки, пока режим включён)
- «Подробный журнал игры» — уровень отладки у игры, Fabric, Forge, NeoForge.
- «Отладчик Java» — порт 5005 (IntelliJ IDEA: Remote JVM Debug), игра не ждёт отладчик. В урезанной Java без
  отладчика флаг пропускается, в журнале запуска об этом строка.
- «Mixin: сохранять изменённые классы» — папка `.mixin.out` сборки.
- «Команды в любом мире» — перед запуском включает читы во всех мирах сборки, после игры возвращает как было
  (и при следующем запуске, если лаунчер закрыли посреди игры).

## Тот же доступ без MCP
```bash
curl http://127.0.0.1:47615/api -H "Authorization: Bearer <ключ>"
curl -X POST http://127.0.0.1:47615/api/list_instances -H "Authorization: Bearer <ключ>" -H "Content-Type: application/json" -d "{\"testOnly\":true}"
```
Ответ: `{ "ok": true, "result": ... }` или `{ "ok": false, "error": "...", "denied": true }` (403 — игрок не разрешил).

Код: `src/src/main/dev/` (сервер, инструменты, защита, флаги запуска), раздел настроек — `devSection.js`,
вопрос игроку — `devConfirm.js`.
