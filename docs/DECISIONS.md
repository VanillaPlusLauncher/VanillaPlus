# Решения и ловушки

Почему сделано так, что пробовали и что не сработало. Ищи по заголовку; новое добавляй в свой раздел.

## Версии и обновления
- **Схема `X.Y.Z` без беты** (с 2026-11-07, решение пользователя, после 1.7.1-beta.8): каждое обновление
  прибавляет единицу к последней цифре: 1.7.2, 1.7.3 … 1.7.9, после 9 — 1.8.0 (и так же 1.9.9 → 2.0.0).
  Слова «beta» в номере больше нет. Такие сборки выкладываются в обычную ленту (`latest.json`, `latest-win7.json`,
  Mac — канал release): `publish-site.ps1` сам выбирает канал по имени файла. Если положить их в бету, лаунчеры
  без «beta» в номере не увидят обновление (они читают только `latest.json`, а Mac отказывается от беты).
  Игроки на 1.7.1-beta.N получают 1.7.2 из `latest.json`: 1.7.2 новее любой 1.7.1-beta.
- Раньше (2026-10-23 … 2026-11-07) была схема `X.Y.Z-beta.N`: пользователю не нравились номера вида «beta 64».
- **Меньший номер не доходит до игроков**: лаунчер берёт только более новую версию. Поэтому 2026-11-01 оставили
  1.7.1-beta.3, а не 1.0.1-beta.3. Для будущей перенумерации есть «эпоха»: `VERSION_EPOCH` в
  `src/src/main/updates/updateService.js` и `"epoch"` в ленте (нет поля = 0); большая эпоха новее любых номеров.
  Перенумеровать: `VERSION_EPOCH = 1` в сборке И сайт пишет `"epoch": 1` в ленты (сайт этого пока не умеет).
- Версия в `src/package.json` остаётся 1.7.0: настоящую версию передаёт `-Version` при сборке.
- Обновления проверяются и на сайте, и на GitHub, побеждает новейшая (1d2b739): падение одного не мешает.
- Неудачная установка обновления не повторяется сама, чтобы лаунчер не закрывался по кругу.
- Windows 7/8 — отдельная сборка на Electron 22 (последний, что там работает) со своими лентами `*-win7.json`.
- Mac: Electron 43 (работает с macOS 12) и подпись ad hoc — открывается через «Всё равно открыть», без Терминала.

## Заметки к версиям
- Заметка на сайте и в окне обновления — одна короткая строка о том, что получает игрок («Ускоренная загрузка модов.»).
  Без внутренностей и истории. Для Mac — только подсказка «Открывается без Терминала: …»: карточка версии на сайте
  показывает две строки и обрезает остальное. CHANGELOG (для разработчиков) может быть подробным.

## Сервер Amethyx
- **Ушли с Cloudflare на PHP-хостинг сайта** (`website/cloud`, 2026-11-01): Cloudflare заблокирован в России, у друга
  пользователя не грузились картинки и сборки. Старый воркер (`server/`) ещё работает для необновлённых лаунчеров;
  выключить его — решение пользователя.
- **Перенос данных больше не запускать**: импорт сначала очищает базу сайта, а игроки уже пишут в новую.
- Новые сообщения лаунчер узнаёт, спрашивая сервер раз в несколько секунд (почему не постоянное соединение — не записано).
- Хостинг принимает запросы до 8 МБ (`post_max_size 8M`): большие файлы идут частями до 7,2 МБ.
- Хостинг стоит за своим фронт-сервером: адрес игрока берётся из его заголовков; подделку проверяли (7e18b24).
- Если сайт Modrinth/CurseForge не отвечает напрямую, лаунчер берёт то же через сервер Amethyx (только с этих сайтов).

## Друзья и игра
- **Панель поверх игры вместо мода в игре** (2026-10-22): мод нужно собирать под каждую версию и загрузчик, а панель
  работает везде и ничего не кладёт в игру. Мод «Пригласить друга» (сессия B) на паузе.
- Друзья заходят в мир напрямую: лаунчер открывает порт на роутере (UPnP) — так работает и там, где Cloudflare
  заблокирован. Раньше заходили через туннель Amethyx; e4mc лаунчер больше не ставит. Нужен «белый» адрес;
  с «серым» лаунчер прямо говорит, что лучше мир откроет друг.
- «Умный помощник» без ИИ и без оплаты: проверки — собственные правила лаунчера.
- Вход Microsoft живёт 24 часа, и первое «Играть» за день ждало цепочку Live → Xbox → XSTS → Minecraft (2026-11-05).
  Теперь вход обновляется заранее в фоне (`startSessionRefresh`: за 3 часа до конца, проверка раз в 30 минут),
  а на «Играть» — одновременно с установкой и Java; синхронизация скина запуск не ждёт.
- Сочетание панели (2026-11-06) — строка-ускоритель Electron (`Ctrl+Alt+O`), клавиши читаются по `event.code`
  (не зависят от раскладки). Правила одни в двух местах — `main/settings/hotkeys.js` и `renderer/js/core/hotkey.js`,
  менять вместе: буквы, цифры, пробел — только с Ctrl или Alt (иначе клавиша не печатает в чате игры); F1–F24,
  Insert, Delete, Home, End, PgUp, PgDn — можно одни; Tab, Enter, стрелки — с любым модификатором; сочетания Windows
  (Alt+Tab, Alt+F4…) запрещены. Старые значения `shift-tab`, `alt-x`, `f9` переводятся сами.
- «Открывать лаунчер после игры» по умолчанию выключено: игрок, закрывший игру, обычно уходит. В режиме «Прятать»
  перед `hide()` ставится значок у часов (`ensureTray`), иначе окно нечем вернуть.
- Друзья общие для всех аккаунтов (просьба пользователя 2026-11-07, по умолчанию включено): на сервере друзья
  привязаны к аккаунту, поэтому друзья, чат, «в сети» и новости идут от одного аккаунта — `socialAccountId()` в
  `cloudClient.js` (`settings.social.friendsAccountId`). В первый раз выбирается аккаунт с сервера, у которого больше
  всего друзей и заявок. Выключено (`sharedFriends: false`) — как раньше, от выбранного аккаунта. Скины и `packFiles`
  остаются у выбранного аккаунта. Окно настроек никогда не отправляет `friendsAccountId` обратно (его держит main).

## Скины в игре без мода
- Версии до 1.7.6 (и 1.7.2–1.7.5 с authlib) берут скин каждого игрока сами по нику обычным HTTP
  (`skins.minecraft.net`, `s3.amazonaws.com/MinecraftCloaks`, `minecraft.net/skin`). Лаунчер даёт игре
  `-Dhttp.proxyHost` на свой прокси и отвечает: свой скин → облако Amethyx `/csl/<ns>/<ник>.json` → Mojang или Ely.by.
  Так видны скины Amethyx всех игроков без CustomSkinLoader, для любого аккаунта. Для Ely.by на 1.7.2–1.7.5
  выключен `legacySkinPolyfill` authlib-injector, чтобы запросы шли к прокси.
- Версии 1.7.6+ чужие скины сами не спрашивают: берут из профиля, который присылает сервер мира, и показывают,
  только если текстуры подписаны ключом, которому игра доверяет, а адрес картинки — с разрешённого сайта.
  Решение (2026-11-06): облако подписывает скины своим ключом RSA-4096 (`lib/signed.php`, ключ в `cloud_state`
  'skin_key'), а лаунчер офлайн-игрока говорит игре доверять этому ключу (`signedSkins.js`, `skinServer.js`).
  - authlib-injector 1.2.8 верит ключу Mojang и только ОДНОМУ ключу из `signaturePublickey`. Поэтому, когда ключ облака
    получен, лаунчер отдаёт его, а не свой. Свой профиль подписывается облаком, если там тот же скин (хеши и модель);
    иначе — своим ключом, как раньше. На 1.20.2+ свой игрок может быть и неподписанным, чужие — только SIGNED.
  - Облако подписывает только свои адреса `/cloud/textures/<sha256>`: иначе любой мог бы получить подпись на чужую картинку.
    Сайт облака добавлен в `skinDomains` (26.x — в `validUris` документа discovery).
  - Хозяин мира (LAN): встроенный сервер спрашивает `hasJoined` про каждого гостя. Лаунчер сначала спрашивает Mojang (4 с)
    для гостей с Microsoft, иначе отвечает офлайн-профилем (id = md5("OfflinePlayer:" + ник)) со скином из облака.
    Встроенный сервер рассылает этот профиль всем в мире.
  - 1.13–1.20.1 на офлайн-серверах сами просят профиль игрока без скина по id: лаунчер спрашивает облако
    `/signed/uuid/<id>.json`. 1.8–1.12 и 1.20.2+ так не делают: там скины видны только в мире по сети.
  - Не работает для аккаунтов Microsoft и Ely.by: их игра не доверяет ключу облака. Проверка библиотекой игры —
    `%TEMP%\rldev\mock\tt\authlib-1106.js` + `authcheck\AuthlibCheck.java` (authlib 1.5.21–10.0.77).
  - Не делать (2026-11-07, решение пользователя): облако не подписывает офлайн-нику скин с Ely.by или Mojang, когда
    в Amethyx скина нет. Иначе любой, введя ник известного игрока, получит и его скин — слишком легко выдать себя за
    другого. Версии до 1.7.6 по-прежнему берут скин Mojang по нику: так делала и сама старая игра.

## Установщик (Inno Setup)
- Папка по умолчанию `%LOCALAPPDATA%\Programs\Amethyx`, не «Документы». Старую установку из «Документов» переносит
  сам и перенаправляет ярлыки (рабочий стол, закреп на панели задач) через WScript.Shell. Чужие ярлыки не трогает.
- `CloseApplications=force`: без него Restart Manager не закрывал вспомогательные процессы Electron, и установка
  поверх открытого лаунчера падала с кодом 5.
- Тестовые установщики собирать из копии .iss со своим AppId, чтобы не задеть настоящую установку.
  Только посмотреть окна можно и с настоящим AppId: собрать с пустым `/DSourceDir` в черновик и открыть без `/SILENT`
  (`/relaunch=1` — окно обновления): до нажатия «Установить» ничего не ставится; закрыть процесс, папку `is-*.tmp` — в Корзину.
- Масштаб окон (2026-11-07): картинки окон рисуются на 100/125/150/175/200/225/250/300 % (`*-<процент>.png/.bmp`),
  `PictureScale` берёт ближайший к масштабу Windows. Раньше были только 1x/2x/3x и при 125 % брались 2x — окна в 1,6
  раза больше задуманного (у пользователя 1920 × 1080 при 125 %). Места в .iss и в скриптах картинок округляются
  одинаково: `ScaledBy` = (v × процент + 50) div 100; в PowerShell `[Math]::Round` округляет к чётному — не годится.
- Значок окна обновления на панели задач (2026-11-08): у окна X был (WM_GETICON отдавал его ещё в 1.7.4), а на панели
  стоял пустой значок программы — Windows 11 берёт картинку кнопки по программе, а Setup работает как `is-*.tmp\*.tmp`,
  у которого картинки нет. Окну даны свойства AppUserModel через `SHGetPropertyStoreForWindow`: ID лаунчера
  `dev.amethyx.launcher` (как `app.setAppUserModelId` в main/index.js), RelaunchIconResource `<папка>\Amethyx.exe,0`,
  RelaunchCommand и DisplayName (без них значок не берётся); WM_SETICON большой и маленький — тоже. В Pascal Script
  строка для PROPVARIANT — `CastStringToInteger` (Setup 32-битный). Ошибка там только пишется в журнал.
- Анимация X в окне обновления (2026-11-08): выбрана «сборка из кусочков» (`installer/art-src/UpdateMark.cs`, кадры
  рисует `make-update-art.ps1`). Кусочки садятся без отскока и разлетаются ровно от центра: отскок и случайный разлёт
  пользователь назвал «тряской». Покачивание вверх-вниз отвергнуто («туда-сюда качается»). Кадры — полоска BMP,
  72 кадра за 3,6 с; число кадров и период в `Amethyx.iss` должны совпадать с `$frames` в скрипте.

## Производительность интерфейса
- Лаги страницы сборки (2026-11-01): ушедшие страницы оставались под видимой с opacity 0, а анимации text-shadow,
  filter и box-shadow перерисовывали всё окно каждый кадр. Решение: страница через 450 мс «засыпает»
  (`page--asleep`: `visibility: hidden; content-visibility: hidden`), анимации — только opacity/transform
  на псевдоэлементах. Мерить, а не гадать: `contentTracing` и метрики CDP Performance из main-скрипта.
- Списки модов: строки переиспользуются по ключу; тихая перезагрузка ничего не рисует, если ничего не изменилось.
- Ловушка (2026-11-06): раздел настроек перерисовывается целиком после каждого сохранения, и переключатель
  (`createSegmented`) рождался заново — выделение прилетало от левого края. Теперь он помнит последний сдвиг
  по набору вариантов (`recentMoves`, 800 мс), а до первой расстановки выделение скрыто.
- Моды: из jar читается только нужное, результат кешируется на диске (82efbd2).
- Подвисание при быстрой смене (2026-11-07): каждый `morph()` запускал View Transition, а он снимает снимок всего окна;
  переходы наслаивались, и щелчки во время перехода терялись. Теперь, пока идёт переход, новый его пропускает
  (`skipTransition()`, изменение сразу), а `::view-transition` не ловит указатель.
- X начинал заново (2026-11-07): раздел «Обновления» перестраивался на каждом проценте, новый `<img>` запускал
  CSS-анимацию с начала. Теперь при скачивании меняются только строка и полоска, а у `loadingMark()` бесконечные
  анимации получают `startTime = 0` (часы страницы) в первом кадре — любой перерисованный значок идёт в такт прежнему.

## Моды и CustomSkinLoader
- Список содержимого следит за диском (`fs.watch`, `contentWatcher.js`), а не за каждым путём установки:
  точные шаги игрока («мод не появился») не воспроизвелись, а слежение закрывает все пути.
- В Universal jar CustomSkinLoader есть только `fabric.mod.json`, поэтому загрузчики определяются ещё и по файлам
  `META-INF/services` (иначе лаунчер называл его несовместимым с NeoForge).
- Удалённый игроком CustomSkinLoader не возвращается: `overrides.skinsInMods = false` (ключ в OVERRIDE_KEYS
  `instanceStore.js`). Без него скины Amethyx в игре не видны.
- Ловушка (2026-11-05): файлы из .mrpack не попадали в индекс `content.json`, поэтому библиотека не видела Sodium
  из модпака, а зависимости скачивались второй раз. Теперь проект и версия берутся из ссылки `cdn.modrinth.com/data/<проект>/versions/<версия>/`,
  а «Установлено» сверяется ещё по modId из jar и по названию (`titleKey`).
- Зависимость «уже есть», только если её файл лежит в mods (запись индекса без файла не считается), а для Modrinth
  ещё и если slug проекта совпал с modId какого-нибудь jar (Fabric API с CurseForge).
- Обновление выключенного мода оставляет его `.disabled`. Пока игра запущена, обновлять моды нельзя: Windows не даёт
  удалить открытый jar, и в mods оставались две версии.

## Звуки
- Ловушка (2026-11-05): общий звук щелчка (`installGlobalSounds`, capture) звучал вместе с явным `sfx()` в обработчике
  (списки, окно версий, переключатели) — два звука на щелчок. Общий звук теперь откладывается на один тик и не играет,
  если за это время уже прозвучал любой `sfx()` (счётчик `playedCount`). Новые кнопки со своим звуком так и пишут `sfx()`.
- Звук наведения — по списку `HOVER_TARGETS` в `sound.js`: новая карточка или строка, которая должна звучать, вписывается туда.

## Вид лаунчера
- Выбран 2026-10-30: мягкие кнопки, пиксельный шрифт Tiny5, настоящие 3D-иконки из Blender
  (`installer/tools/make-3d-icons.py`). Подробно — docs/LOOK.md.
- SVG/CSS «псевдо-3D» пользователь отверг: 3D — только настоящие модели (Blender установлен на этом ПК).
- «Оставим обычный Майнкрафт» значило только шрифт, а не откат всего вида: перед откатом вида — короткий вопрос.
- Иконки бокового меню (картинки предметов Minecraft) не менять: они пользователю нравятся.
- Сборка на главной (`selectedInstanceId`) выбирается только стрелочкой › в полосе «Играть» (просьба 2026-11-08):
  открыть, запустить или создать другую сборку её не меняет. Нет выбранной (не выбирали или удалена) — при старте
  берётся последняя запущенная, новая сборка становится главной, только если главной нет.
- Окна вне главного (меню трея `trayMenu.js`, карточки `notice.js`) — отдельные data:-страницы без CSS лаунчера:
  вид, шрифт, цвет темы и значки им передаёт `main/popupLook.js` из настроек. Новое такое окно — тоже через него,
  иначе оно останется в одном виде (так меню трея было пиксельным при мягком виде).
- Такие страницы говорят с главным процессом сменой заголовка (`page-title-updated`), не переходом по адресу:
  переход до конца загрузки обрывает `loadURL`, и карточка закрывалась, не показавшись.
- Язык по умолчанию — английский (решение пользователя 2026-11-07: «английский — это международный язык»), какой бы
  язык ни был у Windows. В вопросе при первом запуске английский — большая кнопка 2 × 2, закрыть вопрос = английский.
  Если языка в настройках нет, везде берётся `'en'`: `app.js`, `i18n.js`, `overlay.js`, `tray.js`.
- Перевод (`i18n.js`): после любого другого языка слежение за страницей не выключается и на русском. Иначе страницы,
  которые лаунчер держит готовыми (моды сборки), возвращались на русский с текстом прошлого языка. Известный остаток:
  карточки библиотеки, нарисованные на одном языке, держат его «3 недели назад» до нового поиска.
- Шаблоны со словами `{0} из {1}` ловят и длинные строки: у составных строк («На сервер: {0} из {1} · клиентских: {2}»)
  должен быть свой ключ, иначе переводится только половина. Части, склеенные через « · » («модов: 3 · миров: 1»),
  лучше класть каждую в свой `span`: тогда каждая переводится своим ключом (так в «Другие лаунчеры», 2026-11-07).
- Словари `renderer/i18n/*.json` — JSON в одну строку: скрипт, который их правит, пишет `JSON.stringify(dict)` без
  отступов, иначе весь файл в диффе. После правки — одинаковое число ключей во всех 8.
- «Сборки»: одна кнопка «Добавить сборку» (просьба пользователя 2026-11-07, как в Prism Launcher). Все способы —
  вкладки её окна (`openCreateInstanceModal({ tab })`), новые способы добавлять туда же, а не кнопками в шапку.
- «Копировать сборку…» (2026-11-07, как в Prism): ловушка старого кода — `fsp.cp` первым копировал `instance.json`
  источника, поэтому копия сразу появлялась с тем же именем и запускалась недокопированной. Теперь `beginCopy` пишет
  новый `instance.json` с `copying: true`, файлы копируются в фоне (задача `instance:<id>`, полоска наверху), потом
  `finishCopy` снимает метку. Пока метка есть, сборку нельзя запустить и удалить; метка без идущего копирования
  (лаунчер закрыли посреди) — «Копирование не закончено», такую можно только удалить.
- Кнопки — объёмные клавиши (просьба пользователя 2026-11-07: «чтобы прям эти кнопки были такие 3D-шные»): грань
  снизу — внешняя тень без размытия (`0 var(--key-up) 0 var(--key-side)`), во всех состояниях один и тот же список
  теней, меняются только переменные — поэтому подъём и нажатие плавные. Без `color-mix` (его нет в Electron 22).
- Ссылки открываются внутри лаунчера (просьба пользователя 2026-11-07): `<webview partition="persist:links">`
  в окне (`webPage.js`, `core/links.js`). В `window.js` `will-attach-webview` пускает только http(s) и только этот
  раздел, убирает preload и включает sandbox; разрешения раздела все запрещены; новые окна открываются в том же
  webview. Ссылка Modrinth на другой мод открывается окном мода, CurseForge `linkout` разворачивается. Нет webview
  (вдруг) — системный браузер.
- «Библиотека» помнит площадку для каждой вкладки (`platformByType`): «Карты» уходят на CurseForge (на Modrinth
  карт нет) и раньше так и оставляли CurseForge для модов. Фильтр загрузчика показывается только у модов, а
  без сборки (модпаки) у каждой вкладки свои фильтры (`filtersByType`).

## Режим разработчика и доступ для ИИ (2026-11-07)
- MCP по HTTP (Streamable HTTP без сессий, POST `/mcp`, ответы JSON) внутри самого лаунчера, а не отдельная
  программа-мост через stdio: Claude Code и Cursor подключаются одной командой, ставить ничего не нужно, и всё идёт
  через уже работающий лаунчер (его загрузки, аккаунт, журнал). Тот же код отвечает на `/api/<инструмент>` для скриптов.
- Безопасность: слушаем только 127.0.0.1; ключ `Bearer` (сравнение `timingSafeEqual`); заголовок `Host` должен быть
  локальным (защита от DNS rebinding), запрос с чужим `Origin` отклоняется — веб-страница в браузере не достучится.
  Ключ и порт — `<userData>/dev-api.json`, не в settings.json (настройки уходят в экспорт и в журнал). Доступ
  работает, только когда включены и режим, и «Доступ для ИИ»; выключение режима выключает и доступ.
- Тестовая сборка = флаг `test: true` в instance.json (`instanceStore.normalize` его хранит, копия сбрасывает).
  Группа «Тесты ИИ» — на языке лаунчера (`devTools.js TEST_GROUPS`): названия групп на странице сборок не переводятся.
- Всё, что меняет сборку игрока, проходит `devGuard.allowChange`: вопрос в окне лаунчера (по одному за раз,
  2 минуты без ответа = отказ). Отказ ИИ получает текстом «не повторяй, возьми тестовую сборку».
- `gameService.js` не трогали (его правила другая сессия): `broadcast.js` получил `onBroadcast`, и `devGame.js`
  слушает те же события, что окно (журнал, состояние, вылет); флаги запуска — в `gameLauncher.js` через `devLaunch.js`.
- Ловушка: с `-agentlib:jdwp` урезанная Java (jlink, без `jdwp.dll`) не запускается вовсе. `devLaunch.hasDebugger`
  смотрит файл и пропускает флаг со строкой в журнале. В тестовом профиле `ud-bug` Java 21 именно такая (и без
  части системных библиотек — настоящая игра на ней не идёт): для запуска игры в проверке брать
  `%USERPROFILE%\Tools\jdk-21\bin\java.exe` (`javaMode: 'custom'`).
- Игра, упавшая сразу, бывает уже закрыта к вызову `wait_for_game`: тогда ответ «exited» (по `lastLaunch.fromLine`),
  и ответ ждёт разбор вылета (он приходит через секунды после выхода), чтобы ИИ сразу видел причину.
- Вылет тестовой сборки не открывает окно у игрока (`app.js`): ИИ может ронять её десятки раз подряд.
- «Команды в любом мире» пишет `allowCommands` в level.dat и список миров в `<сборка>/.amethyx/dev-commands.json`;
  возврат — после выхода игры и ещё раз перед следующим запуском (если лаунчер закрыли посреди игры).
- Проверки: `%TEMP%\rldev\mock\tt\dev-1107.js` (доступ, защита, вопросы), `dev-1107b.js` (запуски, отладчик,
  английский), `dev-1107c.js` (вылет без окна). Перед проверкой включить в профиле `dev.enabled` и `dev.api`.

## Ловушки среды
- Пустой `--user-data-dir` всё равно открывает настоящую папку игры `%APPDATA%\.amethyx`: в settings.json
  тестового профиля обязательно `gameDirectory`.
- `node script.js | Select-Object -First 1` убивает node посреди записи: es.json стал пустым и ушёл в 1.7-beta.60.
  После скриптов словарей сверять число ключей во всех восьми файлах `src/src/renderer/i18n`.
- Write в `commitmsg.txt` падает без предварительного Read, а параллельный коммит уходит со старым сообщением
  (50e6539, 47dfa7a). `Set-Content -Encoding utf8` добавляет BOM (попал в заголовок cdf1649).
- Инструменты в `%TEMP%` пропадали при чистке Windows (Inno Setup: «Unknown option /D»), а каждая сессия качала
  свои копии (node 17 штук). С 2026-11-07 (правило пользователя для всех проектов) — одна копия в
  `%USERPROFILE%\Tools`, node/python/gh из PATH; скрипты сборки ищут их там сами. Своих копий не скачивать.
- Electron для Mac раньше лежал в `%TEMP%\amethyx-electron-mac-*`; теперь в `build\electron-mac-<версия>`
  (рядом с `build\Amethyx`, в git не идёт). Копии исходников с ключами (`%TEMP%\amethyx-src-*`) сборка удаляет сама.
- После сборки для Mac PowerShell иногда не запускается (EPERM): сайт проверять через встроенный браузер.
- Чистка 2026-11-02 удалила тестовые профили в `%TEMP%\rldev`; копии скриптов — в резервной копии.
- Музыка, промо-ролики и текстуры Minecraft никогда не попадают в git.
- `git … 2>$null` в Windows PowerShell делает `$?` ложным: цепочка «коммит; if ($?) { push }» однажды не отправила коммит.
- Если в индексе лежат файлы другой сессии, коммитить с путями: `git commit -F <файл> -- <пути>`.
- Windows PowerShell 5.1 читает .ps1 без BOM как ANSI: кириллица в строках скрипта ломает его разбор («ё» становится
  кавычкой). .ps1 с русскими строками сохранять с BOM, как `installer/build.ps1` (Write пишет без BOM).
- Старый `%TEMP%\rldev\php\8.1` был сломан (нет DLL). Рабочий PHP — `%USERPROFILE%\Tools\php74\php.exe`; php.exe
  ломается на очень длинных путях, держать его по короткому пути.
- Встроенный браузер: прокрутка через JS не работает (scroll_to), эмуляция размера сбивает координаты кликов,
  снимки экрана не делаются, когда окно приложения свёрнуто.
