# Решения и ловушки

Почему сделано так, что пробовали и что не сработало. Ищи по заголовку; новое добавляй в свой раздел.

## Версии и обновления
- **Схема `X.Y.Z-beta.N`** (с 2026-10-23, после 1.7-beta.64): пользователю не нравились номера вида «beta 64».
  Следующая после 1.7.1-beta.N — 1.7.1-beta.N+1 или, когда скажет пользователь, 1.7.2-beta. Мелочи копить в крупные обновления.
- **Меньший номер не доходит до игроков**: лаунчер берёт только более новую версию. Поэтому 2026-11-01 оставили
  1.7.1-beta.3, а не 1.0.1-beta.3. Для будущей перенумерации есть «эпоха»: `VERSION_EPOCH` в
  `src/src/main/updates/updateService.js` и `"epoch"` в ленте (нет поля = 0); большая эпоха новее любых номеров.
  Перенумеровать: `VERSION_EPOCH = 1` в сборке И сайт пишет `"epoch": 1` в ленты (сайт этого пока не умеет).
- Версия в `src/package.json` остаётся 1.7.0: настоящую версию передаёт `-Version` при сборке.
- Обновления проверяются и на сайте, и на GitHub, побеждает новейшая (1d2b739): падение одного не мешает.
- Неудачная установка обновления не повторяется сама, чтобы лаунчер не закрывался по кругу.
- Windows 7/8 — отдельная сборка на Electron 22 (последний, что там работает) со своими лентами `*-win7.json`.
- Mac: Electron 43 (работает с macOS 12) и подпись ad hoc — открывается через «Всё равно открыть», без Терминала.

## Заметки к версиям
- Заметка на сайте и в окне обновления — одна короткая строка о том, что получает игрок («Ускоренная загрузка модов.»).
  Без внутренностей и истории. Для Mac — только подсказка «Открывается без Терминала: …»: карточка версии на сайте
  показывает две строки и обрезает остальное. CHANGELOG (для разработчиков) может быть подробным.

## Сервер Amethyx
- **Ушли с Cloudflare на PHP-хостинг сайта** (`website/cloud`, 2026-11-01): Cloudflare заблокирован в России, у друга
  пользователя не грузились картинки и сборки. Старый воркер (`server/`) ещё работает для необновлённых лаунчеров;
  выключить его — решение пользователя.
- **Перенос данных больше не запускать**: импорт сначала очищает базу сайта, а игроки уже пишут в новую.
- Новые сообщения лаунчер узнаёт, спрашивая сервер раз в несколько секунд (почему не постоянное соединение — не записано).
- Хостинг принимает запросы до 8 МБ (`post_max_size 8M`): большие файлы идут частями до 7,2 МБ.
- Хостинг стоит за своим фронт-сервером: адрес игрока берётся из его заголовков; подделку проверяли (7e18b24).
- Если сайт Modrinth/CurseForge не отвечает напрямую, лаунчер берёт то же через сервер Amethyx (только с этих сайтов).

## Друзья и игра
- **Панель поверх игры вместо мода в игре** (2026-10-22): мод нужно собирать под каждую версию и загрузчик, а панель
  работает везде и ничего не кладёт в игру. Мод «Пригласить друга» (сессия B) на паузе.
- Друзья заходят в мир напрямую: лаунчер открывает порт на роутере (UPnP) — так работает и там, где Cloudflare
  заблокирован. Раньше заходили через туннель Amethyx; e4mc лаунчер больше не ставит. Нужен «белый» адрес;
  с «серым» лаунчер прямо говорит, что лучше мир откроет друг.
- «Умный помощник» без ИИ и без оплаты: проверки — собственные правила лаунчера.
- Вход Microsoft живёт 24 часа, и первое «Играть» за день ждало цепочку Live → Xbox → XSTS → Minecraft (2026-11-05).
  Теперь вход обновляется заранее в фоне (`startSessionRefresh`: за 3 часа до конца, проверка раз в 30 минут),
  а на «Играть» — одновременно с установкой и Java; синхронизация скина запуск не ждёт.
- Сочетание панели (2026-11-06) — строка-ускоритель Electron (`Ctrl+Alt+O`), клавиши читаются по `event.code`
  (не зависят от раскладки). Правила одни в двух местах — `main/settings/hotkeys.js` и `renderer/js/core/hotkey.js`,
  менять вместе: буквы, цифры, пробел — только с Ctrl или Alt (иначе клавиша не печатает в чате игры); F1–F24,
  Insert, Delete, Home, End, PgUp, PgDn — можно одни; Tab, Enter, стрелки — с любым модификатором; сочетания Windows
  (Alt+Tab, Alt+F4…) запрещены. Старые значения `shift-tab`, `alt-x`, `f9` переводятся сами.
- «Открывать лаунчер после игры» по умолчанию выключено: игрок, закрывший игру, обычно уходит. В режиме «Прятать»
  перед `hide()` ставится значок у часов (`ensureTray`), иначе окно нечем вернуть.

## Скины в игре без мода
- Версии до 1.7.6 (и 1.7.2–1.7.5 с authlib) берут скин каждого игрока сами по нику обычным HTTP
  (`skins.minecraft.net`, `s3.amazonaws.com/MinecraftCloaks`, `minecraft.net/skin`). Лаунчер даёт игре
  `-Dhttp.proxyHost` на свой прокси и отвечает: свой скин → облако Amethyx `/csl/<ns>/<ник>.json` → Mojang или Ely.by.
  Так видны скины Amethyx всех игроков без CustomSkinLoader, для любого аккаунта. Для Ely.by на 1.7.2–1.7.5
  выключен `legacySkinPolyfill` authlib-injector, чтобы запросы шли к прокси.
- Версии 1.7.6+ чужие скины сами не спрашивают: берут из профиля, который присылает сервер мира, и показывают,
  только если текстуры подписаны ключом, которому игра доверяет, а адрес картинки — с разрешённого сайта.
  Решение (2026-11-06): облако подписывает скины своим ключом RSA-4096 (`lib/signed.php`, ключ в `cloud_state`
  'skin_key'), а лаунчер офлайн-игрока говорит игре доверять этому ключу (`signedSkins.js`, `skinServer.js`).
  - authlib-injector 1.2.8 верит ключу Mojang и только ОДНОМУ ключу из `signaturePublickey`. Поэтому, когда ключ облака
    получен, лаунчер отдаёт его, а не свой. Свой профиль подписывается облаком, если там тот же скин (хеши и модель);
    иначе — своим ключом, как раньше. На 1.20.2+ свой игрок может быть и неподписанным, чужие — только SIGNED.
  - Облако подписывает только свои адреса `/cloud/textures/<sha256>`: иначе любой мог бы получить подпись на чужую картинку.
    Сайт облака добавлен в `skinDomains` (26.x — в `validUris` документа discovery).
  - Хозяин мира (LAN): встроенный сервер спрашивает `hasJoined` про каждого гостя. Лаунчер сначала спрашивает Mojang (4 с)
    для гостей с Microsoft, иначе отвечает офлайн-профилем (id = md5("OfflinePlayer:" + ник)) со скином из облака.
    Встроенный сервер рассылает этот профиль всем в мире.
  - 1.13–1.20.1 на офлайн-серверах сами просят профиль игрока без скина по id: лаунчер спрашивает облако
    `/signed/uuid/<id>.json`. 1.8–1.12 и 1.20.2+ так не делают: там скины видны только в мире по сети.
  - Не работает для аккаунтов Microsoft и Ely.by: их игра не доверяет ключу облака. Проверка библиотекой игры —
    `%TEMP%\rldev\mock\tt\authlib-1106.js` + `authcheck\AuthlibCheck.java` (authlib 1.5.21–10.0.77).

## Установщик (Inno Setup)
- Папка по умолчанию `%LOCALAPPDATA%\Programs\Amethyx`, не «Документы». Старую установку из «Документов» переносит
  сам и перенаправляет ярлыки (рабочий стол, закреп на панели задач) через WScript.Shell. Чужие ярлыки не трогает.
- `CloseApplications=force`: без него Restart Manager не закрывал вспомогательные процессы Electron, и установка
  поверх открытого лаунчера падала с кодом 5.
- Тестовые установщики собирать из копии .iss со своим AppId, чтобы не задеть настоящую установку.

## Производительность интерфейса
- Лаги страницы сборки (2026-11-01): ушедшие страницы оставались под видимой с opacity 0, а анимации text-shadow,
  filter и box-shadow перерисовывали всё окно каждый кадр. Решение: страница через 450 мс «засыпает»
  (`page--asleep`: `visibility: hidden; content-visibility: hidden`), анимации — только opacity/transform
  на псевдоэлементах. Мерить, а не гадать: `contentTracing` и метрики CDP Performance из main-скрипта.
- Списки модов: строки переиспользуются по ключу; тихая перезагрузка ничего не рисует, если ничего не изменилось.
- Ловушка (2026-11-06): раздел настроек перерисовывается целиком после каждого сохранения, и переключатель
  (`createSegmented`) рождался заново — выделение прилетало от левого края. Теперь он помнит последний сдвиг
  по набору вариантов (`recentMoves`, 800 мс), а до первой расстановки выделение скрыто.
- Моды: из jar читается только нужное, результат кешируется на диске (82efbd2).

## Моды и CustomSkinLoader
- Список содержимого следит за диском (`fs.watch`, `contentWatcher.js`), а не за каждым путём установки:
  точные шаги игрока («мод не появился») не воспроизвелись, а слежение закрывает все пути.
- В Universal jar CustomSkinLoader есть только `fabric.mod.json`, поэтому загрузчики определяются ещё и по файлам
  `META-INF/services` (иначе лаунчер называл его несовместимым с NeoForge).
- Удалённый игроком CustomSkinLoader не возвращается: `overrides.skinsInMods = false` (ключ в OVERRIDE_KEYS
  `instanceStore.js`). Без него скины Amethyx в игре не видны.
- Ловушка (2026-11-05): файлы из .mrpack не попадали в индекс `content.json`, поэтому библиотека не видела Sodium
  из модпака, а зависимости скачивались второй раз. Теперь проект и версия берутся из ссылки `cdn.modrinth.com/data/<проект>/versions/<версия>/`,
  а «Установлено» сверяется ещё по modId из jar и по названию (`titleKey`).
- Зависимость «уже есть», только если её файл лежит в mods (запись индекса без файла не считается), а для Modrinth
  ещё и если slug проекта совпал с modId какого-нибудь jar (Fabric API с CurseForge).
- Обновление выключенного мода оставляет его `.disabled`. Пока игра запущена, обновлять моды нельзя: Windows не даёт
  удалить открытый jar, и в mods оставались две версии.

## Звуки
- Ловушка (2026-11-05): общий звук щелчка (`installGlobalSounds`, capture) звучал вместе с явным `sfx()` в обработчике
  (списки, окно версий, переключатели) — два звука на щелчок. Общий звук теперь откладывается на один тик и не играет,
  если за это время уже прозвучал любой `sfx()` (счётчик `playedCount`). Новые кнопки со своим звуком так и пишут `sfx()`.
- Звук наведения — по списку `HOVER_TARGETS` в `sound.js`: новая карточка или строка, которая должна звучать, вписывается туда.

## Сайт
- Хостинг кеширует .js/.css сутки: после правки — ссылки `?v=<8 символов SHA-256>` в `website/index.html`
  и `website/admin/index.html` (3f0eae7). Жалоба «ничего не поменялось» — сначала сравнить файл на сервере с репозиторием.
- Пакет для сервера — без комментариев (посетитель прочитал в DevTools, как открыть панель владельца).
  В репозитории комментарии остаются. Никаких скрытых входов и подсказок про админку на публичных страницах.
- Настоящие текстуры аметиста Minecraft — только на сервере (`website/assets/mc/`, в .gitignore), выбор пользователя.
- На сайте без эмодзи (рисованные иконки, d9274b1).
- Сайт живёт на хостинге владельца (ispmanager, nginx → Apache, PHP 7.4+), архивы он заливает сам (docs/SITE.md).
  Первый план — статичный сайт на GitHub Pages (`docs/website-prompt.md`) — устарел: нужны админка и ленты обновлений.
- Защита админки после случая с комментарием (d967ad3): вход только POST с заголовком `X-Amethyx: 1`; блокировка
  5 неверных попыток за 15 минут и 20 в сутки с одного адреса; сессия строгая (12 ч без действий, максимум 3 дня),
  привязана к хешу пароля (смена пароля закрывает другие сессии); CSP и заголовки безопасности в `website/.htaccess`.
- Адрес посетителя (`amx_client_ip`, be2b914): до правки все посетители шли с адреса фронт-сервера хостинга, и чужие
  неверные пароли закрывали вход владельцу. Правило то же, что у `cloud_client_ip`; подделку заголовков проверили вживую.
- `website/cloud/.htaccess` повторяет защиту корня: папка со своим `RewriteEngine On` не наследует правила родителя.
- Ролики сайта (`website/assets/video/`) с музыкой — только на сервере, не в git. Новый вариант трейлера (2026-10-31)
  пользователю не понравился: на сайте остаётся прежний.

## Ловушки среды
- Пустой `--user-data-dir` всё равно открывает настоящую папку игры `%APPDATA%\.amethyx`: в settings.json
  тестового профиля обязательно `gameDirectory`.
- `node script.js | Select-Object -First 1` убивает node посреди записи: es.json стал пустым и ушёл в 1.7-beta.60.
  После скриптов словарей сверять число ключей во всех восьми файлах `src/src/renderer/i18n`.
- Write в `commitmsg.txt` падает без предварительного Read, а параллельный коммит уходит со старым сообщением
  (50e6539, 47dfa7a). `Set-Content -Encoding utf8` добавляет BOM (попал в заголовок cdf1649).
- Чистка Windows удаляет портативный Inno Setup из `%TEMP%` («Unknown option /D») — переустановка в docs/RELEASE.md.
- После сборки для Mac PowerShell иногда не запускается (EPERM): сайт проверять через встроенный браузер.
- Чистка 2026-11-02 удалила тестовые профили в `%TEMP%\rldev`; копии скриптов — в резервной копии.
- Музыка, промо-ролики и текстуры Minecraft никогда не попадают в git.
- `git … 2>$null` в Windows PowerShell делает `$?` ложным: цепочка «коммит; if ($?) { push }» однажды не отправила коммит.
- Если в индексе лежат файлы другой сессии, коммитить с путями: `git commit -F <файл> -- <пути>`.
- Windows PowerShell 5.1 читает .ps1 без BOM как ANSI: кириллица в строках скрипта ломает его разбор.
- `%TEMP%\rldev\php\8.1` сломан (нет DLL). Рабочий PHP — `%TEMP%\rldev\php74\php.exe`; php.exe ломается на очень
  длинных путях, держать его по короткому пути.
- Встроенный браузер: прокрутка через JS не работает (scroll_to), эмуляция размера сбивает координаты кликов,
  снимки экрана не делаются, когда окно приложения свёрнуто.
